# 空间意象：完整制作管线

[English](pipeline.md) · 方法文档：CC BY 4.0，来源与改编见 [NOTICE](../NOTICE.md)。

SDK 是执行工具，设计表是制作合同，成片才是验证对象。调用几个函数不代表完整走过管线。下面每一步都保存真实产物；未执行的步骤记“未验证”或“不适用”。

v0.2 的 [脚本出片入口](script-to-video.zh-CN.md) 将脚本、可配置模型/已审定设计表、素材获取、动画工程、声音和渲染串起来；它执行下面流程中的适用阶段，不替代素材审看和成片检查。音乐、人声、纯程序动画、画幅、时长与风格按项目配置，旧片的零 BGM、特效数量和场景造型不成为通用限制。

## 制作标准 3.24：从意向推导设计

实际规划器现在同时读取随包发布的设计原理、设计推导、本 SOP 和 JSON 合同；工程保存完整指令及各源文件哈希。设计理由、意向链、交接和专项计划进入制作记录，观察与认可独立填写。默认引擎执行二维/CSS 2.5D 图层；真实三维、布料等需求必须声明自定义实现，不能静默降成平面替代品。详见[设计合同与执行边界](script-to-video.zh-CN.md#设计合同与执行边界)。

通用要求是意向、运动、镜头、声音、证据与素材身份。人物 A/B、抠像和重打光属于出镜口播的适用分支；歌词、品牌和其他非口播片不强制人物、浮卡、进度条、书房背景或固定章节数。

先理解[设计原理](design-principles.zh-CN.md)：关系如何进入意象、什么视觉线索维持识别、构图如何组织注意、维度如何改变空间读法、镜头与动作怎样分工、节奏和字体如何承载感受。关键设计写出原理依据、适用理由、预期感知及失败风险；原理名、技法名和责任声明都不能替代这个推导。

新片与主要视觉返修先读[设计推导](design-synthesis.zh-CN.md)。制作者负责提出并选定意象路径与镜头，比较关键替代方案，将取舍、可见中间态、镜头发现和阅读落点写入原设计表；不等待用户逐镜给创意。2D、2.5D、3D、歌词和实拍按表达选择，无原片不自动进入全三维建景。用户要求跨维度时记录实际转换接口，不把3D运镜代签成2D/3D往返。此更新细化设计方法，机器门禁仍为schema 4，不自动评判创意质量。

先确定本句要推进的理解、情绪和注意力，再设计形态、用途、空间、镜头和声音。每镜明确：**原话/文字/动作 → 之前的理解 → 之后的理解 → 可见变化 → 主体交接 → 镜头发现 → 阅读落点**。即使真的做了形变，表达与本句无关也不通过。无口播片按屏幕文字、动作或创作意向设计，不强造语音重点词。

已认可的愿景片与接力测试提供两类基准：流星带镜头逐级扩大观看范围，宇宙结构再收进真人身后的玻璃球，让愿景回到讲述者；引路圆片接成旋钮顶盖，再由特写揭示部件结构，让同一主体改变用途。这些是意向与观看的连续性，不要求所有镜头用同一个网格。基准只复用适用机制，不固定宇宙、玻璃球、旋钮、配色或节拍；新片记录其实际参考版本、区间和改造。

| 门禁 | 所需证据 | 未通过时 |
|---|---|---|
| G1：设计可执行 | 全范围 SH/TR、真实语义窗口、理解/情绪推进、主体职责与去向、镜头任务和声音意图 | 修对应设计；位移、缩放、淡化和换字不能签成内部转化 |
| G2：动态设计成立 | 有声草样覆盖全部 SH/TR；正常速度及前中后检查；意向表达、内容针对性、注意力接力、语义时机、理解落点五项逐一记录；合画面听审 | 修复已知问题后再正式渲染；允许诊断草样，不重复索取已有授权 |
| G3：最终编码可交付 | 当前最终文件的逐镜检查、顺看、听审及媒体技术证据，绑定版本、范围和 SHA256 | 保持测试版/待审/返修状态，不登记完整通过 |

片头通过不能替中后段签字，技术同步/响度不能代替听感；同一物体变形与新主体接棒分别记录，主体可完成职责后退场。有理由的硬切和阅读保持可以成立，换字套效果、无理由清空重开不能满足意向接力。意向、代码、剪点、混音或媒体改变后重新核对受影响镜头与接口，旧证据不能直接移到新版本。

**执行器边界（v0.4）：** 生成工程随带 schema-v4 Python 校验器、Node 门禁入口、绑定当前输入的未审核索引和[独立使用说明](../templates/production/PRODUCTION-GATES.md)。正式 render 执行 G1/G2，`gates delivery` 将 G3 绑定最终编码；诊断使用明确的 `--draft` / `render:draft`。工具检查记录、当前源码/媒体哈希与覆盖范围，不自动判断审美或代替试听。结构校验、实际审看与用户认可分别记录。

八项独立否决门现已覆盖设计、运动、镜头、衔接变化、调色/打光、抠像、降噪与音效。设计逐镜及全片检查，禁止以重复卡片换字、淡入、位移和缩放制作 PPT 式影片。调色/抠像/降噪须有对齐比较，未适用项须有真实源检查证据。具体字段与退回条件见[八项门禁](../templates/production/SPECIALIST-GATES.md)。

## 执行 SOP：输入、动作、产物、退回位置

设计原理说明为什么，SOP规定怎样把判断变成作品。执行顺序以此表为准，下方编号章节提供各专题细则；镜头与证据始终沿用同一SH/EL/TR/VID/SFX，不另建重复台账。

| 阶段 | 输入与必须执行的动作 | 产物与检查；失败返回哪里 |
|---|---|---|
| 1 范围与输入 | 核对用户要求、源文件/脚本/音乐、媒体规格、当前版本；登记talking-head或general及样片/全片范围 | 一页基准、源文件身份与媒体记录；缺失或错误的源先修复。无人出镜不强做人脸检测/A-B |
| 2 内容与时间轴 | 口播转录校对、适用粗剪；歌词核对真实演唱、乐句/重音/延音；纯动效按音乐/文字/意向分段 | 内容/情绪段落与统一时间轴、源内→剪后→样片映射；记录实际模型与不确定处，不伪造词时或把原唱套口播剪气口 |
| 3 研究与选材 | 根据初步关系查样片、完整成片参考、视频和现成音效；查看具体区间、作者和使用条件 | 参考机制及改造、VID/SFX候选、已核验/采用/弃用与缺口；候选不足继续搜寻。几张图片或GitHub工具不能代替取得动态素材/声音 |
| 4 设计推导 | 依据设计原理比较意象路径，安排形态承接、主体识别、维度、镜头、节奏、歌词和统一风格 | 选定主线、关键取舍、镜头剧本及失败风险；空洞回到本阶段重设计，素材改变则回3，不以堆模型补创意 |
| 5 设计表与G1 | 将方案落实到SH/EL/TR/VID/SFX、关键构图/中间态、实际帧窗、阅读与声音包络 | 全范围可执行设计表与G1检查；字段齐全不代替设计判断。机制不清回4，缺素材回3 |
| 6 关键动态草样 | 先做最不确定的转换及相邻上下文；使用真实机位、可读文字、候选声音，以阶段7方法审看 | 可播放低成本草样及缺陷；成立后扩展全范围粗样，再精修模型/材质/灯光、调色/抠像和声音；关键段不能替整片签字 |
| 7 全范围检查与返修 | 正常速度看全部SH/TR，再查前中后、合画面听审，独立执行各适用专项 | 当前版本证据及缺陷；设计错回4/5，实现错回6，选材/音色错回3并重对轴。中后段、结尾与有意留白均覆盖；未验证不填通过 |
| 8 当前版本预览 | 先修制作者已知缺陷，再交有声缓存与可拖轴工程，核对用户实际看到的版本 | 预览、工程快照和范围化反馈；已有授权/认可继续有效。只有样片范围时交样片，不自动扩全片或反复审批 |
| 9 正式编码与交付 | G2通过后正式渲染；最终混音编码后重新顺看、逐镜、听审与技术检查，执行G3 | 本次范围内的成片/约定封面、工程依赖、素材与QA、回库记录；任一必要项失败保留待审/返修版，不能冒称最终 |

顺序为 **1→2→3↔4→5→6↔7→8→9**。选材与设计可以相互修正；动态草样先解决观看关系，再提高精度。时间轴改动回2，重算受影响的镜头、文字、素材、人物和声音；视觉或声音局部改动检查相邻接口及实际编码。没有音源时可先做相对时序设计，正式对拍前必须补齐真实时间依据。

G1/G2/G3约束正式生产，明确标注的诊断草样始终可以做。缺口只阻止依赖它的正式产物，不阻止独立工作，也不产生逐阶段用户审批。每次续做在一页基准记录当前阶段、已验证版本、下一项产物和缺口。此文更新不代表旧工程自动升级或另一会话已重新加载。

## 1. 先分清任务与素材

已有口播：核对原片、逐句转录、词级时间和用户修正，先完成有意义的粗剪，保留语言顺序和情绪。不为了迁就动画擅自加速人声。无原片的品牌片：研究、提案、短文案、镜头表、素材、剪辑、合成、发布。局部返修只改受影响的记录及前后接口。

建项目时登记目标受众、核心观点、画幅、帧率、交付长度、是否有人声/音乐、最终平台和制作范围。素材文件保留原始副本与 SHA256。去噪、调色、代理、裁段各有自己的身份，不能悄悄替换原文件。

## 2. 查素材库与样片库

先写关系、对象、材质、动作，再检索，避免先挑特效再硬改内容。

| 库 | 入库内容 | 选用规则 |
|---|---|---|
| 素材库 | 视频、声音、模型、图片、字体、动效源码、参考链接 | 来源、作者、许可、原文件、哈希/commit、规格、可用区间和检查状态齐全 |
| 样片库 | 真正渲染的版本、用途、区间、源工程、使用素材、QA和反馈 | 认可绑定文件哈希、版本与范围；技术通过不等于审美通过 |
| 外部参考 | 作者成片页和研究笔记 | 只是创作参考，不能登记为已下载素材或剪入授权 |

`searchAssets` 是多关键词包含检索；`searchSamples` 默认只查有明确认可范围的样片。没有命中就换动作/材质关键词，并继续外部搜索。高 Star 只代表一个筛选信号，采用前仍核对代码、维护情况和媒体许可。

视频制作必须主动搜索与具体镜头对应的动态视频，实际查看内容、来源和使用条件，将合适部分剪入。几张图片或程序动画不替代这个步骤。若内容不适合任何候选，记录候选和不采用原因，不拿不适合的素材充数。

## 3. 先写完整设计表

一页基准记录观点、视觉语言、光线、排版、色彩、节奏、声音方向、素材缺口和参考版本。分镜主表与明细共用 ID，避免几份互相矛盾的总表。

一页基准同时记录内容→载体可变属性→主体路径、关键方案取舍及需要动态实测的难点。混合维度的EL/TR补起始维度、转换媒介、保留锚点、中间态与结束维度；歌词作为主体时，SH补入字、完整读字窗口、出字及下一意象。按适用镜头填写，不设每镜变形、全片维度比例或固定花瓣/布料模板。

| 记录 | 必填内容 |
|---|---|
| SH 镜头 | 全局 `[from,to)` 帧、台词/重点词、口播专用 A/B 或其他影片 full、主体、初始→动作→结果、镜头观察任务、阅读窗口、素材与声音引用 |
| EL 元素 | 身份、部件、轮廓、结构、关系或用途如何变化；入场、演绎、收束、退场；哪些部分保持可追踪 |
| TR 交接 | 旧主体完成什么、怎么退出；新主体何时接管；镜头方向、屏幕位置、尺寸、速度和落点如何承接 |
| VID 视频 | 原始素材ID、源内入出点、项目入出点、裁切/变速/静帧接棒、原声去留、许可与作者 |
| SFX 声音 | 来源、源内有效区间、可闻锚点、角色、动作阶段、处理、音量/声像、淡化、交叉区间、收声时刻 |

出图前用短段落写镜头剧本：观众先看谁，经历什么，发现哪种关系，最后理解什么。文字标签不能替代画面表意。“整理”要看到对象重组，“限制”要看到容量冲突，“接力”要看到注意力交接。

时间单位明确：设计表用整数帧；SDK 运动/声音接口用秒；音频处理按采样点。转换使用 `frame / fps` 和 `round(seconds * sampleRate)`，不写死每帧 1600 采样。

## 4. 主体、相机与空间

每镜都有主要观看对象。对象可变形，也可完成职责后退出，交给下一主体。不能每句清空重启、只换卡片文字，或让一张卡承担所有关系。

写出相机的观察任务：跟随、掠过后揭示、近处观察细节、拉开看结构、跨尺度建立新关系，或通过具体构图和时机改变亲近感、张力与节奏。运镜应有可感知的观看作用，不强迫每镜揭露新事实；长期匀速漂移和绕物旋转不是默认答案。近中远层、前景遮挡、视差和受光共同建立空间，不用标注“3D”代替。

连续运动可用 `motionPath`：中间关键点填写世界单位/秒的 `velocity`，两段使用同一切点速度。省略速度表示该关键点暂停。非零端点速度跨到区间外会停住，因此要继续运动就延长路径，不把端点钳位冒充连续。

`followCamera` 的 offset 是世界坐标偏移；lookAhead 是秒。相机跟随和物体运动分开设计。`project` 把世界点投影到像素，可检查切点的屏幕位置；`handoffDelta` 报告差异，不自动判定好坏。需要连续匹配的接口检查位置、尺度、方向、速度、轮廓与运动阶段；有意硬切写清叙事理由。

## 5. 口播专用 A/B、抠像与打光

**仅 `videoType: talking-head` 使用 A/B。** 宣传片、产品片、纯动画和没有出镜讲述者的旁白片使用 `videoType: general`、`state: full`；按主体、场景和镜头编排，full 不是固定单镜头或静态大屏。不能为套管线强造人物小窗。

A 态：真人大屏主导。元素在身后完整空间运动，真实人物蒙版负责遮挡。保护脸、手、字幕和关键文字；大屏尽量不用线条引导。不能只把一个固定侧边卡片变来变去。

B 态：内容接管大屏，真人小窗有合适的空间归属；真人比例和切点按信息需要决定。A→B、B→A、B 内换景分别设计主次、去向与落点，不机械交替。

先匹配原片机位、透视、主光方向、色温、曝光、黑位和清晰度，再处理发丝/衣服残色、边缘光与阴影。调色要比较原片、合成帧和最终编码，避免把色彩解释错误当作曝光问题。二维局部柔光与完整物理重打光要分开命名，不虚构人物侧面和背面。

本 SDK 首版没有转录、抠像或重打光模型。这些是外部制作步骤；设计表记录其真实工具、输出和检查结果。

## 6. 先找声音，再做声音表

用“物件/材质 + 动作 + 有效长度”检索，例如 `paper unfold close`、`glass slide on wood`、`soft air passby long`。根据动作寻找原生主体够长的声音，短按钮 click 不能撑起几秒变形。

候选至少检查：有效主体与文件总长、人声/音乐/杂音、主瞬态位置、自然收尾、声道/采样率、作者与许可。记录试听、解码、选用和未采用分别是什么状态。Sonniss 等能用于成片的素材，不因此自动允许把原声放进开源模板；可再分发的 CC0 也保留作者/来源便于追溯。

声音按职责安排：主运动声覆盖过程，材质层补充物性，接触短声只负责到位。不要每个元素或重点词都自动触发一次 click。音乐按影片目标决定；有配乐时先确定脉冲、段落起落和留白，让语言与画面有节奏，不用音乐掩盖不成立的剪辑。

## 7. 处理、惯性与混音

推荐顺序：原始备份 → 解码/统一采样率 → 裁有效区间 → 必要滤波 → 控制异常瞬态 → 调主体电平 → 运动/材质包络 → 声像 → 人声闪避 → 总线余量 → 编码。

- **对齐可闻点**：`alignSound(actionTime, sourceAnchor, sourceIn)`，不是把文件头放在动作帧就结束。
- **先查主体太小的原因**：裁到静音、瞬态压住主体、淡化过长、频率掩蔽、相消。不能只抬总音量，也不能逐段抬高静音尾巴。
- **惯性来自过程**：起势逐渐进入，随本次速度/阻力/形变变化，减速后收声。读取真实轨迹速度时注明来源；通用包络标为近似。静止阅读可以安静，不能持续沙沙铺底。
- **淡化有角色**：几毫秒去点击不能代替可感知起势；接触音又不应被长渐入磨掉。fadeIn+fadeOut 不能大于事件长度，SDK 会拒绝这种配置。
- **材质交接有重叠**：匹配交接区主体电平，旧声还在退出，新声已经接入。低相关录音可试 `crossfade` 等功率权重；相关源可能出现鼓包，要听实际结果。
- **声像跟观看位置**：以相机相对声源的位置为准。相机追上物体后不能还机械地把它甩到远处。SDK 等功率声像不是完整 HRTF 或物理多普勒。
- **保护口述**：减少竞争事件，再处理时间/频段/电平；闪避平滑恢复，不每次呼吸都抽动。人声、素材原声、音效、音乐独立控制，防止双重原声。

`gainEnvelope` 按音频采样率输出增益，避免用 30 Hz 的阶梯音量处理整段音轨。SDK 不自动选音、生成音源或决定素材许可，例片使用现成音效。

## 8. 验证难点，再完成成片

先制作覆盖真正难点的代表区间，检查主体身份、变化中间态、镜头落点和声音交接。不要用无关的简单段落代表复杂转场通过。测试长度按内容决定。

输出有声缓存 MP4 供观看，保留可拖轴工程。按绝对帧求状态，固定任何随机种子；禁止依赖上帧累积、壁钟或未固定随机。变速后同时重算镜头、素材、字幕和声音，不能只变画面。

连续审看和逐帧检查各有用途：正常速度看阅读与节奏；密集帧看跳位、露底、遮挡、裁字；单听主声、逐层恢复，再合画面听。解码成功、关键帧好看、用户认可和代理听审是不同证据。

## 9. 编码、交付与回库

核验视频流真实帧数、PTS/DTS、FPS、音视频时长、色彩转换和标签、解码错误、音频峰值和首尾。不要仅看容器时长；不同 timebase 的段落不可未经验证直接 stream-copy 拼接。

交付可播放成片、设计表、源码/依赖锁、素材使用清单、处理配置和 QA。技术通过、正常速度观看、声音试听、未解决问题分别记录。没有听过不能写“听感已通过”；没有用户反馈不能自动写“已认可”。

将实际成片 SHA256、版本、规格、适用区间、素材引用和反馈回样片库。新版本新增记录，旧版不覆盖。外部链接仍属于参考，不升级为本地已完成作品。公开前仅发布有权再分发的资产，其他资产保留可复现的获取入口与身份。
