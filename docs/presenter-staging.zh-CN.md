# A/B 主次交接与人物避让（3.24）

A/B 只用于出镜口播：A 由人物主导，B 由动画、演示或素材主导，人物收小并有明确位置。**A/B 的背景场景必须不同。** 空间连贯来自设计好的过渡，而不是保留同一张背景。只缩小人物、放大内容窗口、改底色或改场景名都不能满足要求。歌词、品牌等非口播影片继续用 `full`。

## 设计顺序

1. 根据本句确定观众应看表情还是看过程，再选状态，不按固定秒数轮换。
2. 分别画 A/B 的落稳构图：人物在哪，主体是什么，内容占多大，镜头让观众发现什么，何时可以阅读。A/B 分别设计不同的背景场景，B 态给演示对象足够空间和观看尺度。
3. 写完整接管与返回：旧主体完成什么、内容如何展开/变形/进入特写、人物如何让位、下一主体如何接住注意力。保留身份、空间方向和动势，不用清空重开代替交接。
4. **先给信息留位置，再安排人物路径。** 关键文字、图表、结构关系、操作细节和变化的中间态均须保护。人物身体与手势不能遮住正在讲解的必要信息；装饰对象可以经过人物身后。检查整个转场，不只看首尾。冲突时调整构图、人物裁切/大小/位置或对象路线。
5. 先做最危险接口的动态草样。正常速度看编码视频，再看起始、中间、落稳及最接近的帧。保留阅读时间，不以无休止运镜代替设计。

## SDK 的可执行设计表

每个 A/B 镜头必须填 `staging`；字段和完整限制见[英文契约](presenter-staging.md)。

| 字段 | 必须落地的内容 |
|---|---|
| `scene / purpose / framing` | 环境身份、本句为什么用该状态、实际构图 |
| `presenterLayers` | 实际动态人物视频层 ID，不能用静态肖像或形状冒充 |
| `contentLayers` | 本镜主要演示内容；B 必须有真实内容 |
| `environmentLayers` | 明确的背景场景及装饰，不能为空；与人物、主要内容分开 |
| `protectedLayers` | 不可被人物遮挡的信息层，必须包括本镜文字和所有 A/B 讲解内容；装饰对象归环境层 |
| `landing` | 位于镜头内的全局 `[开始帧,结束帧)` 落稳区间 |

`intent.focusAfter`：A 指向人物，B 指向内容。相邻 A↔B 的 `takeover` 必须记录 `environment`（变化 transformed / 替换 replaced；不接受保留同背景）、`reason`、`reveal`、`bridge`、`completionFrame` 、`proofLayers` 和 `environmentProofLayers`。完成帧位于下一镜和接口审核范围内，且不晚于落稳开始；内容证明层必须是实际内容，不能只填人物；背景证明层必须引用两态实际环境。两态 `scene` 身份必须不同。不要把“放大”写成结构变化；布局接管与内容表意是两项检查。

默认 2D/2.5D 渲染器会逐整数帧投影人物和信息层的可见矩形，拦截重叠，包括转场中间帧。落稳时 A 的人物可见矩形并集面积应大于主内容，B 相反；分散小物体之间的空白不会计入面积。背景证明在落稳的每一帧须覆盖至少 90% 画幅，防止用小浮层冒充换场；两端背景的媒体/形状身份须不同，同文件改名会通过资产哈希识别，只调色或缩放同背景不通过。接口还会比较内容及观察状态，只改场景名、只动人物无法满足接管条件。导入设计、模型修复、草样渲染和门禁都落实这些约束。

这是保守布局检查，不是自动抠像识别、美术打分或像素级可读性判断。透明空隙、圆角、文字框留白仍按矩形占位；应收紧保护框、分离必要细节与装饰底板，留出实际手势空间。自定义三维渲染器仍必须写上述设计，并用真实输出的投影/遮挡证据和逐镜观看验收，不能用默认 CSS 的矩形检查冒称它已经通过。不得把渲染器改名为 custom 来躲门禁。

透明人物视频层使用 `transparent: true`，保证抽帧保留已有 alpha。这不会自动修复抠像、残边或光线。人像融合仍按调色门和抠像门检查。

## 各门必须记录什么

| 门 | A/B 新增检查项 | 实际观察 |
|---|---|---|
| 设计 | `ab_scene_role`、`ab_background_distinction`、`information_clearance` | 本句主次是否有理由，两态是否各有构图，人物路径是否避开信息 |
| 动画 | `ab_content_priority`、`ab_background_distinction`、`information_clearance` | 内容确实接管并有过程，人物移动期间是否盖住过程或结果 |
| 镜头 | `ab_view_change`、`ab_background_distinction`、`information_clearance` | A/B 观看任务是否变化，重要细节是否处于有效尺度；固定机位须说明理由 |
| 衔接 | `ab_takeover`、`ab_background_distinction`、`information_clearance` | 开始、途中、落稳、返回均有承接，人物和内容没有互相抢占信息区 |

设计/动画检查每个 A/B 镜头，镜头门另检查 A↔B 接口，衔接门检查每个 A↔B 接口。各门还必须观察两态背景是否实际不同、变化是否明显且有动机、换场过程是否接得住；不能以背景文件名不同代替可感知差异。G1 审设计，G2 看草样实际编码，G3 重看最终编码；必须写具体对象、位置、帧号和结果，不能填“没问题”。矩形通过、播放器能播放、音轨存在，都不等于美术或听感通过。

这些字段进入工程设计表和审核哈希。修改保护区域、人物或内容路线后，执行 refresh 会清除旧审核，必须重新渲染与检查。旧 A/B 工程需补齐字段并更新运行代码和专项审核；schema 仍为 4，但旧通用勾选不能替代新要求。没有 A/B 的 general/full 工程不增加这些字段。
