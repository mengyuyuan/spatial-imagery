# 原片保真、声音剪辑与返修坑位

版本3.25.0，2026-10-04。适用于实拍/原声输入，以及用户反馈画面糊、声音小、剪不清、抠不干净或处理未落实的返修。纯程序动画只应用编码、动态审看与交付部分。本细则接入原九步和已有八项门禁，不要求新项目固定用PNG、CRF10、30fps或ProRes，也不增加用户审批次数。

## 1. 先分清损失发生在哪一层

先检查当前实际文件，不凭文件名、录制设置记忆或转发渠道猜测。保留源文件路径/哈希与完整ffprobe记录：宽高、编码/像素格式、`avg_frame_rate`和`r_frame_rate`、时长、实际帧数、码率、matrix/transfer/primaries/range、音频采样率/声道。判断VFR、帧率矛盾或截段尾部时再检查PTS与解码帧。用户说1080p60、实际收到1080p约30时，分别说明“收到文件规格”和“原设备设置未知”；没有传输前原件就不能断言是微信压缩，也不能重复帧后称原生60fps。

画质诊断按同一时刻建立四个观察点：**原片解码RGB → 处理后的原生前景 → 合成原帧 → 实际编码解码帧**。先通过剪辑表把输出帧映射回源时刻；统一裁切、显示尺度与颜色解释，再比脸/发丝/衣服和运动边缘。不要用不同帧、整幅深色背景平均分或播放器缩放截图证明人物没损失。

原拍摄本来偏软、低清代理放大、前景模型重建变软、过度降噪/磨皮、反复编码和播放器缩放是不同问题。先定位再处理；锐化、AI补细节和提高码率都不能证明找回了原本没录到的信息。

## 2. 坑位表：症状、定位、修复与验收

| 坑与识别信号 | 必须怎么处理 / 退回哪里 | 验收证据与不能冒称的事 |
|---|---|---|
| 原片已经软，粗剪CRF20→调色H.264→合成H.264又压几遍 | 回Step1/6，画出源→处理→合成→交付路径；保留剪辑表，从原片重建。质量敏感或反复合成采用PNG/适合的无损中间编码；预览走独立低成本分支 | 当前编码与合成原帧同帧人物ROI对比，另查源→前景是否先丢细节。仅给旧MP4升码率不算返修 |
| 文件标1080p但人物像低清放大；60fps源不见了 | 查每层真实宽高/FPS、缩放/裁切、模型推理尺度、渲染scale、Canvas DPR及采样映射；按输出约定回连原生输入 | 报告真实收到规格和每层处理尺寸；输出容器1080p不证明有效细节1080p；降帧/补帧必须如实登记 |
| RVM前景比原片蜡、糊，alpha却看似正常 | 回抠像实现。核对模型输出foreground是否重建/降采样；不透明核心优先保留同帧原RGB，仅软边必要时做前景恢复/去溢色，再按计划调色 | 分别看源RGB、模型foreground、alpha、最终前景。未调色核心可像素对照；调色后与同处理参考比，不能伪称与未调色原片逐像素相同 |
| 椅背、窗帘、底部残块随人物带入新背景 | 回抠像/跟踪，用亮底、暗底和实际背景连续检查；在人物局部坐标做辅助遮罩/修边，随A/B变换；不能用大模糊或粗裁手指遮错 | 头发/眼镜/手指/衣角/身体下缘及转头抬手全过程；核对RGB与alpha同帧。存在alpha文件不等于抠干净 |
| 声音变小、水下感、辅音没了，却写“降噪成功” | 回连续未降噪参考；旁路处理做时间对齐、等响度对听。减轻/撤掉伤害可懂度的降噪，按需要另做增益、局部自动化与限幅 | 记录原声/处理声/最终混音的试听范围、实际损伤与电平。LUFS、RMS、峰值和相关性不证明听得清；禁止为过固定RMS门槛猛抬底噪 |
| 含糊原话被ASR猜成“合作过”等错误含义 | 回Step2，结合前后句自行定位复听，采用用户已纠正原话；确实无法辨认标未核准。用户说“我没有合作伙伴”不能改成相反事实 | 转录、字幕、卡片同一准确版本；只有改文字不能声称修复了含糊录音。配音/声音克隆不能擅自增加 |
| “到达”前重复/口吃还在，只把字幕改顺了 | 在真实源内音画上删除失败起句，保留完整“当我到达一万粉的时候”等有效句；修剪点两侧呼吸、词头、词尾与动作，重映射所有依赖 | 保留删除区间及源→剪后映射，正常速度听整个句子和接缝、看口型；不能只看波形或ASR文本 |

| A/B背景一样，人物或手挡住讲解过程 | 回[人物避让](presenter-staging.md)，分别设计背景场景与主次交接；先定信息保护区，再定人物路径 | 全部转场及落稳区间看背景接管和关键内容可见性。装饰可穿身后，必要信息不能靠“人物小了”直接判通过 |

| 20MB被当成糊的唯一原因，1GB又被当成清晰保证 | 查时长、编码器、质量控制、内容复杂度、有效像素和实际损失；通过对照选择编码设置 | 报告实际字节、视频/音频/总码率及参数。低码率静态画面可正常，高码率也可保留原有模糊；ProRes422HQ和H.264 CRF10都非数学无损 |

## 3. 制作与返修的保真路径

- **优先路径**：原始媒体 + 源内剪辑表 → 原生尺寸处理/合成 → 高质量合成参考 → 各交付编码。预览代理单独生成并标 `preview-only`；正式入口核对所有实际输入路径，避免错误回连代理。
- **源偏软或反复合成**：优先减少有损代际。可选择RGB/RGBA PNG、适合当前解码器的无损视频；核对透明度、像素格式和色彩，估算存储与I/O。不是所有片强制PNG。高质量中间编码在权衡后可用，但如实标有损，不叫无损母版。
- **保留原有细节**：RGB与alpha分别可追溯；低分辨率蒙版可以是算法选择，但须检查最终边缘。不要把低清模型foreground扩大替代全分辨率人物核心，也不要因为最终输出1080p就忽略纹理实际分辨率。
- **最终有损只做所需次数**：各版本尽量从同一高质量合成源直接编码；交付MP4和ProRes保存版不能互相层层转码。无修改的封装/流复制不算再次编码，但仍检查时间戳、音轨和兼容性。
- **有损质量参数按片选**：CRF值、目标码率、preset、GOP和保存格式以当前编码器及内容为准；文件体积不是目标。先用包含脸/衣料/手势/图形的代表片段比较，再套当前输出设置。必要时提高质量，而不是为方便预览长期保留粗剪压缩链。
- **音频单独保真**：连续剪后未降噪参考与最终混音保留PCM；多个AAC片段不要直接盲拼，最终统一编码。人声含糊先诊断录音和剪点，降噪、增益、压缩、限幅分别登记目的和影响。

渲染失败/补渲时保留已验证完整帧；只复用输入、帧映射和实现没有改变的区间。改变素材末帧处理等逻辑后，明确首个受影响帧并重渲该范围及接口，不以文件存在认定可复用。需要维护递归模型状态时，不能无依据从任意源帧跳起。

## 4. 证据接到已有门禁，不另造批准流程

在一页基准填写“源规格/源缺陷、预览与正式媒体路径、尺寸/FPS映射、音频旁路参考、调色/塑光目标、交付格式与编码设置”。实际结果保存在已有项目技术QA报告；文件名不强制，以下内容适用时不能省略：

1. **身份与链路**：原文件与各关键中间物/输出的路径、角色和SHA256；源与输出各自宽高/FPS/实际帧数/时长；源内→剪后→样片映射及是否缩放/降帧/补帧；已知源缺陷与无法恢复的范围。
2. **编码可追溯**：实际渲染器/版本、实际编码器/版本、运行命令或脚本哈希、质量控制（如CRF或码率）、preset、GOP、像素格式、色彩转换与标签、音频格式、实测码率和文件字节。FFprobe的encoder标签不一定完整，不能从标签或体积推断CRF/渲染器。
3. **分层对照**：输出帧和源时刻映射、同裁切/同显示尺度/同色彩条件、脸/发丝/衣物/运动边缘的实际观察；质量指标注明参照和范围，不将PSNR变化换算成“清晰几倍”。调色差异与编码损失分开比较。
4. **声音与剪辑**：用户纠正的文字、删除区间、PCM参考、处理链及时间对齐/等响度条件；原声和处理声/最终混音的真实试听范围与问题；技术偏移/响度/真峰值另记。不能实际听审就填未验证，不假装听过。
5. **结论与缺口**：技术检查、逐镜动态、抠像/光色、听审、用户认可分列。当前最终编码的全片解码与正常速度顺看/听审缺一，不能称全部通过；诊断/待审版仍可交付并继续修复。

把上述报告/链路文件作为 `inputs` 的真实文件身份纳入现有绑定，技术检查挂 `technicalReview.evidence`，光色/抠像/降噪对应既有comparison和checks；台词/剪点进原时间轴与声音审查。旧schema4结构不变，本次没有给所有外部SDK自动安装新逻辑。检查器只能核对记录/文件与测量，不能自动证明没有代理污染、听清了人声或完整遵守美术要求。

`verify_delivery.py`报告文件哈希、字节和探测的编码规格，执行尺寸/FPS/帧数/解码/目录检查；平均/峰值电平只是技术观测。`--min-mean-db`与`--max-peak-db`仅在项目明确需要该测量门槛时传入，它们是dBFS而非LUFS/真峰值，不能命名成“人声可懂度通过”。纯无声片可使用 `--audio-mode optional`允许无音轨，并仍执行既有声音门的 `silence_review`；该参数本身不证明输出无杂音。
